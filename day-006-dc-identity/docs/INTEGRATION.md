# 개발자 연동 체크포인트

[온라인 연동 가이드](https://dc-identity.web.app/?guide=1&section=examples) · [소개](../README.md)

1. 서비스에 가입·로그인한 뒤 개발자 콘솔에서 본인 웹사이트와 정확한 Redirect URI를 등록합니다.
2. SSO 로그인과 기존 회원 인증 API 중 필요한 방식을 고릅니다. REST 인증 API는 Confidential 서버 앱으로 사용합니다.
3. 인증 여부만 필요한지 DC 식별 코드도 필요한지 선택합니다. 식별 코드에는 등록 권한과 사용자 동의가 필요합니다.
4. 내 앱을 선택한 가이드에서 실행 예제와 설정 안내를 내려받습니다. Client Secret은 서버 환경변수로만 설정합니다.
5. 실제 요청에서 로그인·동의·취소·콜백·코드 교환을 테스트합니다. 실패·취소·만료 결과를 회원 인증 성공으로 처리하지 않습니다.

| 비교 항목 | SSO / OIDC | 인증 REST API |
| --- | --- | --- |
| 시작할 때 | 로그인할 외부 사용자 | 이미 로그인한 외부 회원 |
| 외부 서비스의 결과 | 검증한 신원으로 회원 조회·가입·로그인 | 시작한 기존 회원에게만 인증 연결 |
| 검증 | state·PKCE S256·필요한 nonce, JWT 서명·issuer·audience·만료 | 기존 회원·CSRF·state·PKCE, 등록 Client와 콜백에 묶인 일회용 코드 |
| 현재 상태 | 해당 Client의 UserInfo | 해당 인증 API 토큰의 신원 조회 |

기본 로그인 버튼, 팝업, 자체 UI와 일반 링크를 선택할 수 있습니다. 고정된 로그인 상세 URL을 복사하지 말고 서비스의 시작 경로에서 새 요청을 생성합니다. 로그인·동의 화면은 제공되는 인증 페이지를 이용합니다. 팝업의 완료 알림 자체를 로그인 증거로 삼지 말고 서버에서 확인한 세션을 다시 읽습니다.

권장 확인 항목은 제공 범위별 결과 필드, 사용자의 동의 취소, 잘못된 콜백 주소, 코드 만료·재사용, PKCE 불일치, 연결 해제 후 온라인 상태입니다. 외부 서비스의 자체 계정·권한·회원 탈퇴·세션 만료 정책은 외부 개발자가 관리합니다.

[브라우저 화면 체험](https://dc-identity.web.app/examples/)은 UI 시뮬레이션이며 토큰을 발급하지 않습니다. 실제 프로토콜 테스트는 등록한 Client와 본인 서버에서 실행한 예제를 사용합니다. 예제의 메모리 세션과 테스트 회원은 운영 회원 DB나 영속 세션의 대체가 아닙니다.
