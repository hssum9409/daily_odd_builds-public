# Codex Usage Monitor Scripts 1.5.2 — 배포 안내

모든 배포물은 OS 내장 런타임으로 실행되는 스크립트입니다. 1.5.2는 Windows 작업표시줄 위젯의 가림과 숨긴 모니터의 복구 경로를 개선합니다. 기존 공개 ZIP은 교체하지 않고 새 버전으로 제공합니다. Mac은 **전체 기능 실기기 미검증 preview**를 유지합니다.

## 1.5.2 변경 사항

Windows 작업표시줄 위젯의 실제 창 순서를 확인합니다. 1.5.1에서는 좌표와 TOPMOST 속성만 같으면 배치를 생략해, 작업표시줄 뒤에 가려진 상태를 놓쳤습니다. 필요한 때만 작업표시줄 바로 위로 복구하고 트레이 팝업을 덮지 않습니다.

패널 숨김 상태에서는 트레이 아이콘 OFF 선호와 별도로 복귀용 아이콘을 유지합니다. 패널 복원 후에는 원래 선호를 따릅니다. Windows 시작 메뉴·포터블과 Mac 실행기를 다시 실행하면 숨김 상태의 설정을 열 수 있습니다. Windows 로그온 등록은 명시적인 백그라운드 실행으로 구분하며 자동 시작·업데이트가 임의로 설정창을 열지 않습니다.

실제 Explorer에서 구버전의 가림을 재현하고 수정본의 표면 복구·팝업 순서·불필요한 반복 배치 방지·포커스 유지를 검사했습니다. Windows/Mac 설치형·포터블·자동 업데이트 파일을 함께 갱신합니다. Mac은 실기기 미검증 preview를 유지합니다.

## 1.5.1 변경 사항

Windows 대시보드가 우측 패널의 자동 접힘에서 복원될 때 위로 튀던 문제를 수정했습니다. 중간 회피 높이는 표시하지 않고 최종 위치를 확인한 뒤 복원합니다. 설정창을 열어도 마지막 정상 위치를 유지하며, 설정창이 Codex 뒤에 가려지던 창 순서를 정리했습니다.

작은 창이나 숨겨진 아이콘 팝업이 전면에 왔다는 이유만으로 대시보드 전체를 숨기지 않습니다. Codex 소유의 비최상위 창으로 다른 창이 덮은 부분만 자연스럽게 가려집니다. 최소화·종료·이동 중 숨김 처리는 유지합니다.

현재 보고 있는 로컬 대화의 토큰·캐시·속도 기록을 따라갑니다. 명시적으로 대화 ID를 지정하면 그 설정을 우선하며, 원격·새 대화·모호한 다중 창 상태에서는 다른 대화의 값을 대신 표시하지 않습니다. Work의 대화ID_실행ID 기록 파일도 지원합니다. 비용은 단가를 설정한 경우의 환산치이고, 속도는 완료된 턴의 시간 기록이 있어야 표시합니다.

세션 로그는 처음 한 번 최근 최대 8MiB를 읽은 뒤 추가된 부분만 처리합니다. 부분 행·UTF-8·CRLF·중복·파일 교체를 처리하고 읽기·메모리 예산을 제한합니다. 데이터 갱신에서는 대시보드 컨트롤을 재사용하고, 작업표시줄 위젯은 별도 PowerShell 대신 본체 내부의 C# UI 스레드로 실행합니다. 반복 배치·상태 파일 디코드·진단 작업도 줄였습니다.

실제 일반 실행에서 사용자가 한글 입력·포커스·설정 열기·접힘/복원·부분 가림과 토큰 표시를 확인했습니다. CPU는 입력 주입·브라우저 제어 없이 프로세스 카운터로 관찰했습니다. 성능 개선율이나 모든 PC에서의 동일한 동작을 보장하지 않습니다. Windows/Mac 설치형·포터블·자동 업데이트 파일을 함께 갱신하며, 새 대시보드 개선은 Windows 전용이고 Mac preview는 유지합니다.

## 1.5.0 변경 사항

Windows에 Codex 창 부착 대시보드와 작업표시줄 위젯을 추가했습니다. 기존 Pet 위/아래·별도 표시 방식은 유지합니다. 창 부착은 Codex 테마를 따르고 원형 게이지와 초기화·크레딧 안내를 내부에 표시합니다. 폭에 따라 기본형/좁은형을 자동 선택하고 우측 패널이 열리면 요약으로 접습니다. 창 이동·크기 변경 중에는 숨었다가 안정된 위치에 다시 나타납니다.

톱니바퀴로 설정을 열고 옆 아이콘으로 접기·펼치기를 전환합니다. 지정한 대화의 로컬 기록에서 세션 토큰·캐시 적중률·환산 비용·출력 속도를 표시하며 각각 끌 수 있습니다. 비용은 입력한 단가의 환산치이며 실제 청구액이 아닙니다. 단가 미설정·미지원 데이터는 값을 만들어내지 않습니다.

작업표시줄 위젯은 숨겨진 아이콘 화살표 왼쪽에 원형 게이지·퍼센트·초기화까지 남은 시간을 표시합니다. 5시간·주간 한도가 함께 제공되면 모두 표시합니다. 라이트/다크 테마와 호버·클릭 효과를 지원하고 클릭하면 설정을 엽니다. 기본 OFF입니다.

조회 중·갱신 지연·연결 오류를 구분합니다. 창 메시지마다 PowerShell을 호출하던 경로를 C# 필터로 바꾸고 이벤트 관찰을 필요한 범위로 줄였습니다. 일반 실행에서 한글 입력·포커스·접기/펼치기를 사용자와 확인했습니다. 툴팁 호버만으로 배치를 바꾸지 않으며 세션 로그는 필요한 이벤트만 디코딩합니다.

Mac은 기존 Pet 기능의 preview를 유지합니다. 신규 창 부착·작업표시줄 UI는 Windows 전용입니다. Mac 전체 설치·권한·Pet 추적·자동 업데이트는 실기기 검증이 완료되지 않았습니다.

## 1.4.13 변경 사항

Windows/Mac 모두 마지막 정상 예고와 확인 시각을 로컬에 저장합니다. 표시 중 종료한 알림은 재실행 직후 무음으로 복원하고, X로 닫은 알림과 알림 OFF 설정은 유지합니다. 조회가 30분 이상 지연되면 안내를 없애는 대신 ‘소식 갱신 지연’을 표시합니다. 캐시는 마지막 정상 확인 후 최대 48시간 보관하며 조짐 유효기간과 완료 확인을 우선합니다. 정식 예고의 예상 시각이 지나면 최대 6시간 ‘확인 중’으로 표시하고 종료합니다. 시각 미정 예고도 발표·최초 발견 후 최대 48시간까지만 유지합니다.

손상 JSON과 잘못된 응답 구조에서는 마지막 정상 정보를 보존합니다. 검증된 본문과 ETag·확인 시각을 함께 저장하고, 대응하는 본문 없이 304를 받으면 조건 없는 재조회로 복구합니다. Windows에서 정상 304 때문에 재시도 간격이 증가하던 문제를 수정했습니다. HTTP 상태·오류 종류·다음 조회 시각·숨김 사유는 프로필의 `feed-diagnostic.json`에 기록하며 계정 응답·토큰·원문은 포함하지 않습니다.

Windows App Server 입력도 BOM 없는 UTF-8로 고정합니다. 실행 환경의 콘솔 인코딩에 따라 첫 JSON 앞에 BOM 문자가 붙어 연결이 실패할 수 있는 경로를 막고, 해당 조건을 명시적으로 재현하는 전송 회귀 검사를 추가했습니다.

10분 간격의 50분·40분·20분 전 재알림 누락과 시각 미정 예고를 닫은 뒤 반복되지 않던 문제를 수정했습니다. 구버전 닫기 기록을 이행하고 표시 중인 창은 추가 팝업·소리 없이 갱신합니다. 패널 전체를 한쪽에 놓을 공간이 없으면 메인·리셋·크레딧 카드를 화면 안의 별도 영역에 나누어 표시하며, 사용자의 위/아래 선호 설정은 바꾸지 않습니다.

Windows/Mac 설치형·포터블·자동 업데이트 ZIP에 같은 변경을 적용합니다. Windows 실제 패키지/WPF 프로세스 재실행·로컬 HTTP 오류 주입과 Mac 모의 AppKit·피드 함수, 양 플랫폼 계산 비교를 검사합니다. Mac의 설치·Pet 추적·실제 업데이트 등 전체 장치 검증은 완료하지 않았으므로 preview를 유지합니다.

## 1.4.12 변경 사항

Mac 설치기의 파일 목록 검증·필수 파일 확인·복사가 같은 정규화 사본을 사용합니다. LF·CRLF·혼합 줄바꿈과 마지막 개행이 없는 목록을 처리하며, 다운로드 원본은 수정하지 않습니다. 필요한 파일은 정확한 이름으로 비교합니다. 설치 잠금 폴더의 임시 목록은 성공·실패 시 함께 정리합니다.

잘못된 경로·파일명 내부의 CR·손상된 파일은 계속 거부하고 기존 설치와 설정을 보존합니다. 설치형·포터블·업데이트 ZIP의 같은 설치기를 대상으로 CRLF 신규 설치, LF 갱신, CRLF 복원, 표준/별도 설치 경로와 제거 회귀 검사를 추가했습니다. 검증은 Windows Git Bash의 POSIX 파일 작업과 모의 JXA 범위이며 Mac 실기기 검증을 대신하지 않습니다.

배포 체크섬·manifest는 빌드 OS와 관계없이 LF로 생성합니다. 내부 파일 목록은 원시 바이트부터 검사해 CRLF 생성 회귀를 감지합니다. Windows/Mac 설치형·포터블·자동 업데이트 파일을 모두 1.4.12로 갱신하며 Mac preview 표시는 유지합니다.

## 1.4.11 변경 사항

Pet이 없어서 모니터가 임시로 별도 표시 중일 때, 설정창에서도 ‘펫과 별도 표시’를 선택 표시합니다. Pet이 돌아오면 저장해 둔 위/아래 위치와 선택 표시를 함께 복원합니다. 자동 전환은 복원용 선호값을 저장하거나 덮어쓰지 않습니다.

사용자가 직접 별도 표시나 숨기기를 선택한 경우에는 Pet이 다시 나타나도 그 선택을 유지합니다. 패널 X·트레이 토글·설정 버튼으로 실행 모드가 바뀌면 열린 설정창도 함께 갱신합니다. 언어 변경으로 내용을 다시 만들거나 설정창을 다시 열 때도 현재 모드의 선택 표시를 적용합니다. 짧은 감지 대기와 Codex 비활성 절전 중에는 저장한 선호 위치를 유지합니다.

같은 선택에는 색상을 반복 적용하지 않아 주기 갱신의 추가 작업을 줄였습니다. Windows 실제 WPF/Render 및 Mac 모의 AppKit·공통 로직에서 검사하며, Mac의 전체 기능 실기기 미검증 preview 표시는 유지합니다.

## 1.4.10 변경 사항

Windows에서 작업표시줄용 아이콘·바로가기를 만들지 못해도 설정창을 열 수 있습니다. 같은 아이콘은 다시 쓰지 않으며, 실패하면 다음 설정창 열기에서 같은 창으로 작업표시줄 등록을 재시도합니다. 창을 닫을 때 Shell 정리 실패도 설정창 종료를 막지 않습니다.

설정을 함께 삭제하는 `-Uninstall -PurgeSettings`는 작업표시줄 아이콘과 바로가기 캐시까지 정리합니다. 앱을 먼저 제거한 뒤 설정 삭제를 실행해도 작동합니다. 일반 제거의 설정 보존은 유지하고, 알 수 없는 파일이나 junction으로 연결된 외부 폴더는 삭제하지 않습니다.

Mac의 응답이 정확히 1800초 지난 경계를 Windows와 동일하게 처리하여 리셋 알림을 숨깁니다. 이후 유효한 응답을 받으면 기존 복원·닫기·소리 규칙을 따릅니다. Mac은 모의 JXA·공통 로직·POSIX 셸 검사 범위이며 preview를 유지합니다.

## 1.4.9 변경 사항

업데이트로 꺼졌다 켜진 뒤 리셋 안내가 다음 알림 구간까지 사라지던 문제를 수정했습니다. Windows/Mac 모두 표시 이력과 X로 닫은 이력을 구분합니다. 표시 중이던 유효한 예고·조짐은 재시작 후 소리 없이 복원하고, 사용자가 닫은 알림은 다음 구간까지 숨깁니다. 만료·알림 OFF·오래된 응답에는 복원하지 않습니다. 구버전 기록에는 닫기 여부가 없어 유효한 알림을 소리 없이 복원합니다.

리셋 안내의 `1일 0시간`은 `24시간`으로 표시합니다. 종료 시각 기준 카운트다운과 ‘가능성’ 문구는 유지합니다. 한국어·영어·중국어·일본어에 같은 규칙을 적용합니다.

Windows 설정창의 작업표시줄 아이콘을 지피쨩 얼굴로, 앱 이름을 `Codex Usage Monitor`로 지정했습니다. PowerShell과 별개 앱 ID를 사용하고, 작업표시줄에서 다시 실행하면 설정창을 엽니다. 프로필의 전용 바로가기를 사용해 긴 실행 경로도 처리하며, 창을 닫을 때 Shell 속성 리소스를 해제합니다.

Windows/Mac 설치형·포터블·자동 업데이트 ZIP을 모두 1.4.9로 제공합니다. Mac의 변경 사항은 모의 JXA·공통 로직·POSIX 셸 범위에서 검사하며 preview를 유지합니다.

## 1.4.8 변경 사항

리셋 조짐이 최초 범위인 `within 24h`에 고정되던 문제를 수정했습니다. Windows/Mac 모두 API의 `active_watch.expires_at`에서 현재 시각을 빼서 `리셋 조짐 · 11시간 48분 이내 가능성`처럼 표시합니다. 이미 표시 중인 알림도 API를 추가로 조회하지 않고 분 단위로 감소하며, 종료 시각에 도달하면 숨깁니다.

‘가능성’ 문구와 기존 알림 간격·소리·닫기 동작을 유지합니다. 조짐의 종료 시각은 확정된 리셋 일정이 아니므로 일반/보관형 리셋 예고와 계속 구분합니다. 한국어·영어·중국어·일본어에 같은 계산을 적용하며, 설치형·포터블·자동 업데이트 파일을 모두 갱신합니다. Mac은 preview입니다.

## 1.4.7 변경 사항

Windows 설치 폴더를 PowerShell 작업 위치로 사용하던 1.4.4에서 자동 업데이트할 때, 설치 폴더가 사용 중이라 교체와 복구가 모두 실패하던 문제를 수정했습니다. 설치기·업데이터의 PowerShell 작업 위치와 백그라운드 실행기의 작업 위치를 임시 폴더로 옮깁니다. 기존 1.4.4 업데이터도 새 설치기를 내려받아 사용하므로 별도의 구버전 패치는 필요하지 않습니다.

업데이트 작업 폴더에 `update.log`, `install.stdout.log`, `install.stderr.log`와 복구 단계 로그를 보관합니다. 복구까지 실패하면 `result.json`에 원래 오류·복구 오류·실패 단계·백업 위치를 함께 기록하고 `recovery_required` 상태로 남깁니다. 구버전 업데이터가 실행하는 새 설치기도 프로필의 `install-last-error.json`에 실패 원인을 남깁니다.

Windows/Mac ‘만든놈’과 README의 전체 프로젝트 링크를 [Daily Odd Builds](https://daily-odd-builds-portal.web.app/)로 바로잡았습니다. Mac 기능은 기존 수정 사항을 유지하며 preview로 제공합니다.

## 1.4.6 변경 사항

Windows/Mac 모두 Codex Resets의 `active_watch`를 읽어 `리셋 조짐 · 24시간 이내 가능성`처럼 표시합니다. 일반/보관형 리셋 예고와 문구를 구분하고 기존 알림 디자인·표시/소리 설정·원문 링크를 사용합니다. 유효기간이 지나거나 더 최근의 리셋 완료가 확인되면 숨기고, 정식 예고가 함께 있으면 예고를 우선합니다. 조짐 유효기간을 리셋 예정 시각으로 사용하지 않습니다. 같은 게시물은 중복 알리지 않고 설정된 10분/30분/1시간/2시간 간격에 재표시합니다. 실제 예정 시각에 적용되는 필수 임계 알림은 조짐에는 적용하지 않습니다.

Mac 설치 동의 응답에서 언어를 읽는 셸 코드가 GNU sed 확장에 의존하던 문제를 POSIX 정규식으로 수정했습니다. 취소·설치 진행·잘못된 응답·설치 UI 실패를 터미널에 표시하며, 라이선스 동의 후 실제 설치 스크립트까지 연결되는 배포 ZIP 검사를 추가했습니다. 이 검사는 Windows의 Git Bash/POSIX 모드와 모의 UI 경계를 사용하므로 실제 macOS 설치 성공의 증거는 아닙니다.

Mac 폴더 생성의 ObjC nil 인수, 글자 서식과 렌더링 재시도, 실행 앱 번들 및 중첩 CLI 탐색을 수정했습니다. macOS 14.6.1 / arm64 사용자 진단 v6에서 CLI 발견·프로세스 시작·계정/사용량 응답 수신을 확인했고, 앞선 v4에서 실제 글자 표시를 확인했습니다. 설정창의 지역 함수를 모듈 객체로 호출하도록 수정한 v7 영역은 아직 실기기 미검증입니다. 이 결과를 전체 설치·Pet 추적·업데이트 검증 완료로 확대하지 않습니다.

Mac 백그라운드 실행 오류는 프로필의 `startup.log`에 남기고 직전 로그는 `startup.previous.log`에 보관합니다. 설치 성공 시 `Installed at ...`가 표시됩니다. 기존 Mac 설치가 동의 직후 끝났다면 새 설치 ZIP을 전체 압축 해제해 `Install.command`를 실행하세요.

## 1.4.5 변경 사항

Mac 설치기의 언어 선택·라이선스 동의 창에서 `runModal` 반환값을 함수로 다시 호출하여 설치가 중단되던 오류를 수정했습니다. 실행·대기·종료, 파이프·잠금·타이머·창·애니메이션에도 JXA의 무인수 Objective-C 메서드 접근 규칙을 적용했습니다. 관련 모의 호스트도 함수 대신 getter를 사용하도록 고쳐 재발 검사를 추가했습니다.

Windows/Mac 설치형·포터블·자동 업데이트 ZIP을 같은 버전으로 제공합니다. Windows 기능 변경은 없으며 기존 백그라운드 실행 수정을 유지합니다. 실제 Mac 설치·화면 표시·Pet 추적·업데이트는 아직 미검증입니다. 1.4.4 이하에서 설치가 중단됐다면 새 설치 ZIP을 전체 압축 해제하고 `Install.command`를 실행하세요. 기존 Mac 업데이터에도 같은 호출 오류가 있어 이 수정은 수동 설치를 권장합니다.

## 1.4.4 변경 사항

시작 메뉴·설정 바로가기·자동 시작은 공통 백그라운드 실행기를 사용하고, 설치 직후·업데이트 후 실행도 콘솔과 입출력 핸들을 분리합니다. 구버전 바로가기나 업데이터가 모니터를 직접 실행해도 모니터가 스스로 콘솔에서 분리됩니다. 기존 직접 실행 방식의 자동 시작 등록은 설치 시 이행하며 새 방식의 등록도 갱신·제거 때 올바르게 처리합니다.

## 1.4.3 변경 사항

Windows 포터블의 실행용 CMD 창을 자동으로 닫고, 모니터는 콘솔 창 없는 별도 프로세스로 실행합니다. 시작·새로고침·설정 실행기가 같은 백그라운드 실행 방식을 사용합니다. 기존 CMD를 닫아도 모니터가 종료되지 않습니다.

| 플랫폼 / 방식 | 다운로드 | 실행 |
| --- | --- | --- |
| Windows 설치형 · 권장 | `CodexUsageMonitorScripts-1.5.2-windows-installer.zip` | 전체 압축 해제 → `Install.cmd` |
| Windows 포터블 | `CodexUsageMonitorScripts-1.5.2-windows-portable.zip` | 전체 압축 해제 → `Start.cmd` |
| macOS 설치형 · preview | `CodexUsageMonitorScripts-1.5.2-macos-installer-preview.zip` | 전체 압축 해제 → `Install.command` |
| macOS 포터블 · preview | `CodexUsageMonitorScripts-1.5.2-macos-portable-preview.zip` | 전체 압축 해제 → `Start.command` |

설치형은 Windows `%LOCALAPPDATA%/Programs/CodexUsageMonitorScripts`, Mac `~/Library/Application Support/DailyOddBuilds/CodexUsageMonitorScripts/app`에 복사됩니다. 설치 후 다운로드 ZIP과 원본 폴더를 삭제해도 됩니다. 포터블은 실행 폴더를 유지해야 합니다. 원본 ZIP은 삭제해도 됩니다. 관리자 권한이나 Python/Node 설치는 필요 없습니다.

Mac에서 실행 권한이 유지되지 않으면 터미널에서 압축 해제한 폴더로 이동해 `sh ./Start.command` 또는 `sh ./Install.command`를 실행하세요. Pet 추적에는 접근성 권한이 필요할 수 있습니다. Finder 실행·quarantine·Intel/Apple Silicon·AppKit·launchd·업데이트는 실제 Mac에서 미검증입니다. [MAC-QA.md](MAC-QA.md)를 확인하세요. 보안 정책은 자동으로 변경하지 않습니다.

## 자동 업데이트

공개 저장소 `hssum9409/daily_odd_builds-public`의 `day001-vX.Y.Z` Release를 직접 조회합니다. 별도 서버가 필요 없습니다.

| 설치 / 포터블 | 자동 업데이트 파일 | 교체 대상 |
| --- | --- | --- |
| Windows 둘 다 | `CodexUsageMonitorScripts-windows-update.zip` | 현재 실행 폴더; 설치형은 등록된 설치 경로 |
| macOS 둘 다 · preview | `CodexUsageMonitorScripts-macos-update-preview.zip` | 현재 실행 폴더; 설치형은 설치 영수증 경로 |

설정의 자동 업데이트는 기본 OFF입니다. OFF여도 새 버전을 확인하고 설치 여부를 묻습니다. ON이면 확인창 없이 진행합니다. Codex 활성 시 확인하고 활성 중 6시간 간격으로 조회하며, 비활성 시 조회하지 않습니다. 설정에서 수동으로 새 버전을 확인할 수도 있습니다.

SHA-256·파일 크기·버전·ZIP 경로·payload manifest 검증 → 자기 모니터 종료 → 코드와 에셋 교체 → 재실행 준비 응답 확인 순서입니다. 시작 실패 시 이전 버전으로 복구합니다. 사용자 설정·알림 기록·시작 등록은 유지합니다. 쓰기 권한 없는 포터블 폴더에서는 업데이트할 수 없습니다. 종료 후 쓰기 가능한 폴더로 옮겨 실행하세요. 폴더를 옮겼다면 시작 등록을 해제한 뒤 새 위치에서 다시 등록하세요.

새 버전 없음·미배포·오프라인·손상 ZIP·잘못된 버전은 현재 파일을 유지합니다. 403/429에는 대기 시간을 적용합니다. 이미 실행 중인 업데이트와 중복 실행하지 않습니다. 강제 전원 종료 중의 교체는 원자적인 OS 트랜잭션이 아니므로 완전한 복구를 보장하지 않습니다. 복구용 backup은 프로필의 updates 폴더에 보존합니다.

Mac preview 자산을 받기 위해 Release 자체는 일반 릴리즈로 만들고, Mac 다운로드 이름·문서에 preview를 유지합니다. draft/prerelease Release는 자동 업데이트가 무시합니다. 업데이트 ZIP 두 개와 `SHA256SUMS.txt`를 모두 업로드·검증한 뒤 공개해야 합니다. 체크섬은 파일 무결성 검사이며 배포자 인증용 전자서명은 아닙니다.

## 수동 업데이트 / 제거

설치형은 새 설치 ZIP의 `Install.cmd` / `Install.command`를 실행하면 기존 설정을 보존하며 갱신합니다. 내부 `update.cmd` / `update.command`도 **설치형 갱신용**입니다. 포터블을 유지하려면 자동 업데이트를 사용하거나, 모니터를 종료하고 새 포터블 ZIP을 별도 폴더에 풀어 실행하세요. 기존 설정은 별도 프로필에 남습니다.

설치형은 Windows 설치된 앱/시작 메뉴의 Uninstall, Mac 설치 폴더의 `macos/uninstall.command`로 제거합니다. 기본적으로 설정을 보존합니다. 포터블은 자동 시작을 등록했다면 `remove-startup.cmd` / `remove-startup.command`로 먼저 해제하고, 모니터를 종료한 뒤 실행 폴더를 삭제하세요.
