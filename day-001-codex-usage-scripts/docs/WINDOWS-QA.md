# 1.4.2 설정창 Pet 상태 동기화

설정창을 최초 감지 전에 열면 위/아래 버튼이 비활성화 상태로 남던 문제를 수정했습니다. 열린 설정창은 기존 감지 결과로 활성화 여부를 갱신하며 추가 감지·네트워크 조회나 설정 저장을 수행하지 않습니다. Pet의 재등장/숨김/앱 종료 여부를 표시 옵션에 반영합니다.

# Windows 실사용 QA

검사일: 2026-10-11. Windows 11 x64 / Windows PowerShell 5.1.
기존 설치형 앱과 다른 격리 프로필에서 스크립트 0.1.0을 실행했다.

## 실제 조작과 관찰

1.4.0의 추가 창 검사: 사용량·리셋·크레딧 패널은 `WS_EX_TOOLWINDOW`를 적용하고 `WS_EX_APPWINDOW`를 제거한다. 실제 WPF HWND에서 투명도·최상단·클릭 가능 속성과 숨김/재표시 후 유지까지 20개 검사를 통과했다. 설정창은 작업 전환 가능한 일반 창으로 유지한다. Windows의 Alt+Tab 화면을 직접 열어 목록을 확인하는 수동 검사는 별도 확인 항목이며, HWND 속성 검사를 실제 키보드 조작으로 표기하지 않는다.

트레이 표시 설정은 OFF 시 `NotifyIcon` 등록·메뉴·아이콘 자원을 해제하고 ON 시 다시 만든다. 실제 WPF에서 설정 저장·재열기·중복 생성 방지까지 9개 검사를 통과했다. 패널 배치는 투명 여백(위 16/아래 4 DIP)을 제외한 테두리 기준으로 위 6/아래 12 DIP를 유지한다. 한/세 줄과 예고·경고 조합별 실제 창 치수를 사용하는 16개 검사를 통과했다. 알림 간격 10 DIP와 공간 부족 시 반대편 배치도 유지한다. Mac은 같은 계산을 반영했으나 실제 장치 검증 전 preview다.

이 실사용 검사에 사용한 계정은 현재 PC의 계정 하나다. 다른 플랜/기기에서 같은 결과를 보장하는 검사가 아니다. 초기화권 사용과 크레딧 소모는 수행하지 않았다.

## 재현 및 진단

`tests/startup-real.ps1`은 실제 Run 명령·start.cmd·중복 실행·설정 IPC·종료·자식 정리를 확인하는 14개 검사다. **로그온 테스트가 아니다.** 실제 Codex가 실행 중이어야 한다. Pet을 숨긴 상태에서도 별도 패널이 시작되는지를 허용한다. 등록값을 바꾸는 테스트이므로 검사 동안 다른 프로세스에서 이 제품의 자동 실행 등록을 변경하지 않는다. 정상 종료/오류 시 원래 값을 복구한다.

```powershell
powershell.exe -NoLogo -NoProfile -STA -ExecutionPolicy Bypass -File tests/startup-real.ps1
```

개발용 `-TracePath` 또는 `CODEX_USAGE_SCRIPTS_TRACE`로 상태 변경 JSONL을 기록할 수 있다. 기본값은 기록하지 않음이다. 선호 위치/실제 모드/좌표/창 표시 여부/자기 자식 PID만 기록하며 계정 응답, 인증, 이메일, 다른 창 제목은 저장하지 않는다. 경로의 상위 폴더는 먼저 만들어야 한다. 테스트가 끝나면 해당 옵션/환경 변수를 제거한다.

로컬 증거는 배포에서 제외되는 `.research/windows-real-qa/`와 `.research/startup-real-*/`에 있다. 초기 로그에 위치 미정 값이 `NaN`으로 기록되는 진단 문제를 확인해 `null`로 고쳤다. 제품 상태 전환 오류는 이번 조작에서 재현되지 않았다.

한글·공백 경로의 압축 해제본에서도 같은 자동 실행 검사를 진행했다. 200자짜리 격리 프로필 경로에서 명령의 임시 파일이 Windows 경로 길이 제한을 넘어서 설정/종료 IPC가 실패했다. 명령 ID는 UUID의 128비트 고유값을 유지하면서 구분자만 생략해 파일명을 줄였다. 테스트 실패 시에도 등록값을 반드시 복구하고 자기 자식을 정리하도록 검사 도우미도 보완했다. 수정된 압축 해제본에서 14개 검사를 모두 통과했고 등록값과 자식을 정리했다. PowerShell 5.1의 일반적인 긴 경로 제한을 모두 없앤 것은 아니므로 압축 해제 위치와 별도 진단 프로필은 짧게 유지한다.

## 다음 종료·로그온 검사

1. 중단 가능한 시점에 모니터를 실행하고 Codex를 완전히 종료한다. 창 닫기로 트레이에 남은 상태와 프로세스 종료를 구분한다.
2. 2초 이내 존재 확인 이후 패널이 사라지고, 자기 App Server가 종료되고, usage/feed 조회가 멈추는지 확인한다. API 연결 중 종료도 반복한다.
3. Codex와 Pet을 다시 켠다. 이전 위/아래 선호값으로 복원되는지 확인한다. 명시적인 별도 표시/숨김 설정도 각각 확인한다.
4. ZIP을 고정 폴더에 놓고 자동 실행을 등록한다. 재부팅·로그온 뒤 중복 프로세스/콘솔 창 없이 시작되고, Codex가 없으면 패널이 나타나지 않는지 확인한다.
5. Codex를 켜서 활성화되는지 확인하고 등록을 해제한다. 다음 로그온에서 실행되지 않는지 확인한다. Windows의 시작 앱 사용 안 함 설정도 별도로 확인한다.

## 0.2.0 설치본 추가 검사

다운로드 원본을 삭제한 설치 경로에서 WPF 패널·설정·스타일·만든놈을 실행하고 캡처했다. 설치/실행 중 업데이트/재시작/설정 보존/손상 파일 거부/제거까지 26개 검사를 통과했다. 자동 실행은 다운로드 경로가 아닌 설치 경로를 가리키며, 제거하면 이 버전의 Run 항목·시작 메뉴 바로가기·설치된 앱 등록이 지워진다. 기존 EXE와 프로필은 그대로 둔다.

이번 UI는 원본 Windows 앱의 PNG·ICO·팔레트와 840×720 설정 크기를 적용했다. 같은 fixture의 패널 본체는 원본과 332×64로 일치했다. 현재 버전의 Pet/실제 계정 조회·Run 명령은 재검사했으나, 위 표의 사용자 마우스 드래그·Hide Pet 검사는 0.1.0 당시 증거다. UI 변경 뒤 실제 마우스로 다시 전 구간을 검사한 결과로 바꾸어 쓰지 않는다.

Codex 실제 종료·재실행과 OS 로그온은 다른 중단 불가 작업 때문에 계속 보류한다. 다음 검사의 4번은 ZIP 폴더 유지 대신 `install.cmd -Startup` 설치 후 다운로드 삭제로 진행한다.
