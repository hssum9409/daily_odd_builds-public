# 0.4.0 변경분 동기화

이 문서는 0.4.0 CLI/서버 계약이다. 이전 0.3.1 설치본은 업데이트 전까지 기존 6시간 수집을 사용한다.
0.4.0 배포본 공개/자동 업데이트 배포와 이 코드의 구현·검증을 구분한다.

## 수집과 저장

- 최초 웹 연결과 프로세스 시작 시 즉시 조회한다. 자동 수집을 일시정지한 경우에도
  사용자가 명시적으로 웹 연결을 완료한 직후에는 한 번 조회한다.
- 토큰 원본은 30초 간격으로 조회한다. 느린 요청은 겹치지 않으며 놓친 횟수를 재생하지 않는다.
  정상 시 조회 시작 시각을 기준으로 다음 30초를 잡는다. 운영체제 스케줄링 오차는 존재한다.
- account/read, account/usage/read는 매 조회한다. 사용 가능한 스킬·연결 앱·보유 초기화권과
  한도 윈도우는 시작 시 및 1시간마다 추가 조회한다. 플랜과 최장 턴 등 usage 응답에 함께
  오는 값은 추가 요청 없이 비교한다.
- 토큰, 날짜별 값, 플랜, 각 메타데이터를 마지막 저장 성공값과 비교한다. 바뀐 필드만
  보낸다. 조회 시각만 바뀌면 HTTP 요청도 없다. 선택적 API 실패/필드 생략은 기존 값을 유지한다.
  실제 0, 감소한 수치, 플랜 변경은 변경분이다.
- 서버는 변경분을 RTDB `ingest/{uid}`에 합친다. head는 최신 요약/메타데이터,
  pending.daily는 Firestore에 아직 반영하지 않은 날짜, recentDaily는 최근 40개 비교값이다.
  과거 정정도 pending에 들어간다. 매 샘플을 별도 로그 문서로 쌓지 않는다.
- 최초 원본 통계가 없는 계정은 즉시 Firestore에도 반영한다. 기존 사용자는 본인 통계를
  RTDB에서 즉시 표시하며, Firestore는 매시간 UTC 55분에 변경 사용자만 묶어서 갱신한다.
- 6시간 랭킹 배치 직전에도 대기 변경분을 반영한다. Firestore 커밋 이후의 실제 cutoff로
  순위를 계산하며 새 데이터를 과거 시각으로 소급 표시하지 않는다. 주기(UTC 0/6/12/18시),
  기간/플랜별 공유 top-50 문서, 별도 본인 순위, 잠정/누락 데이터 정책은 유지한다.
- 본인 프로필을 연 사용자만 자신의 RTDB 경로를 구독한다. 다른 사용자 데이터와 전체
  ingest 트리를 읽을 수 없고, 클라이언트의 RTDB/Firestore 쓰기는 계속 차단한다.

## 로컬 상태

Windows `%LOCALAPPDATA%/TokenScaleCLI`, macOS `~/.config/token-scale` 아래:

| 파일 | 용도 |
|---|---|
| state.json | 원본 연결 식별자, 로컬 계정 해시, 메타데이터 조회 시각, 마지막 전송 시각 |
| metadata-cache.json | 마지막 관측 메타데이터. 전송 실패 중 새 관측값도 잃지 않게 분리 |
| statistics-cache.json | 서버가 승인한 전체 통계, epoch/sequence, 미확인 요청과 그 목표 통계 |
| statistics-cache.json.lock | daemon과 수동 sync가 동시에 캐시를 수정하지 않게 하는 파일 잠금 |
| session | Windows DPAPI / macOS Keychain으로 보호된 Firebase 세션 |

통계 캐시에는 허용된 숫자와 날짜만 포함한다. 스킬/앱 이름·경로·대화·코드·OpenAI 인증정보는
포함하지 않는다. 로컬 계정 해시는 전송하지 않는다. 캐시를 지우면 다음 조회에 전체 기준값을
보낸다. 다른 Codex 계정으로 전환하려면 기존과 같이 명시적인 `--reset-source` 동의가 필요하다.

## HTTP 계약

API_BASE는 기존 `GET /v1/collector-config`로 연결 웹을 안내하는 API와 같다.
Firebase Google 사용자의 Bearer ID token을 사용하며 OpenAI 토큰은 받지 않는다.

1. `POST /v1/stream-open`: `{sourceId, proof, resetSource?}`.
   기존과 같은 stdio/version/method allowlist를 검증하고 원본 연결 epoch와 현재 sequence를 반환한다.
   초기화/캐시 복구 시에만 호출한다. proof는 OpenAI가 발급한 서명이나 통계 진위 증명이 아니다.
2. `POST /v1/stream-patch`: `{sourceId, epoch, sequence, patch}`.
   sequence는 직전 승인값 + 1. patch는 아래처럼 변경된 부분만 포함한다.

```json
{
  "summary": {"lifetimeTokens": 12500},
  "daily": {"2026-10-21": {"tokens": 300, "fetchedAt": "2026-10-22T00:00:00.000Z"}},
  "fetchedAt": "2026-10-22T00:00:00.000Z"
}
```

증가분을 더하지 않고 최신 절대값으로 교체한다. 생략은 변경 없음이며 0은 실제 0이다.
서버는 날짜/범위/필드/관측 시각/원본 연결/순번/최소 요청 간격을 강제한다.
성공 응답은 `{changed, sequence, epoch, uploadedAt, verificationStatus}`다.

요청 전 로컬 pending을 원자적으로 저장한다. 서버 반영 후 응답을 잃었거나 프로세스가
재시작되어도 같은 본문/순번으로 재전송하고 같은 receipt를 받는다. 다른 내용으로 같은
순번을 재사용하면 거부한다. 성공 전에는 ACK 기준값을 앞당기지 않는다. 일시 오류는
1/2/4/8/16/32/64분 상한의 backoff를 사용한다. 서버 상태 재설정/관측 만료는 전체 기준값으로
재연결한다. 이 과정에서도 원본 계정 변경을 자동 승인하지 않는다.

기존 `/v1/challenge → submit`은 0.3.1 사용자에게 유지한다. fast stream으로 전환한 UID의
구형 제출은 `collector-upgrade-required`로 거부하여 최신 변경분을 덮어쓰지 못하게 한다.
현재 Node 임베딩 SDK는 이 구형 계약이다. 0.4.0 CLI가 연결된 동일 UID에 혼용하지 않는다.
다른 호스트에서 새 계약을 구현할 때 이 문서와 CLI의 stream_sync.dart를 기준으로 한다.

## 서버 집계와 비용

고빈도 제출은 Firebase Auth 확인과 RTDB 트랜잭션만 사용한다. 최초 연결/원본 변경 외에
Firestore 읽기·쓰기, nonce 문서, 업적 전수 계산을 매 제출마다 수행하지 않는다.
서버의 dirtyAt 인덱스로 오래 대기한 사용자부터 최대 500명씩, 동시 10명씩 처리한다.
집계 시작 후 새롭게 dirty가 된 사용자는 다음 회차로 넘겨 무한 drain을 방지한다.
실패한 사용자와 처리 중 추가된 변경분은 삭제하지 않는다. 포화/실패는 집계 로그에 기록한다.

날짜 이력이 바뀔 때만 이력 기반 업적을 재계산한다. 업적 상태가 같으면 해당 문서를 쓰지
않는다. 집계 사이에 관측된 플랜과 한도 최고치/가용 개수 최고치는 작은 signals로 보존한다.
한도 관측을 실제 초기화권 사용 이력으로 해석하지 않으며, 스킬 가용 개수를 사용 횟수나
설치 플러그인 수로 표시하지 않는다.

RTDB 저장/다운로드, 연결 오버헤드와 HTTPS Functions/Auth 비용은 남는다. 30초마다 숫자가
바뀌는 사용자는 하루 최대 약 2,880회 제출하므로 무료 운영을 보장하지 않는다. 원본 제공자의
집계 지연보다 빠른 최신성을 만들 수 없으며, 앱이 꺼진 동안의 샘플/메타데이터 이력을 만들지 않는다.
검증 상태는 계속 community_reported다.

## 검증 경계

실제 Codex/Google/Firebase를 사용하는 Windows 설치·웹 연결·변경 없는 반복 조회와,
응답 유실/과거 정정을 강제로 만든 Windows 실행 + Firebase emulator 시험을 구분한다.
합성 통계와 오류 주입은 demo-token-arena 에뮬레이터에서만 수행하며 운영 순위에는 넣지 않는다.
실제 OpenAI가 나중에 과거 통계를 정정하는 사건 자체를 재현한 것은 아니다.
