# Day 005 · 성실삐🤖 0.6.0

대시보드 주소: https://bbi.hssum.kr/ (기존 Firebase 프로젝트와 기록 유지).

앱 표시 이름은 성실삐🤖입니다. 기존 설치·계정·설정을 이어 쓰기 위해 패키지와 내부 식별자는 `WorklogScripts`를 유지합니다.

Windows와 macOS 배포판은 Day 1 방식의 명령줄 설치 도구입니다. Windows는 OS에 포함된 PowerShell 5.1/.NET Framework/WPF, macOS는 `/bin/sh`, `osascript` JavaScript/AppKit, `curl`을 사용합니다. 최종 사용자는 Node, Flutter, .NET SDK, Swift 컴파일러를 설치할 필요가 없습니다. 기존 `windows/Worklog`, `macos/` 컴파일형 초안은 참고용이며 현재 배포 대상은 `desktop/`입니다.

## 위젯

Day 1의 작은 프레임을 유지하면서 승인된 A 시안을 기본 **크림**, B 시안을 **차콜 (다크)** 테마로 제공합니다. 크림 배경 `#F5F1E8`과 짙은 글자 `#353A34`, 차콜 배경 `#292C29`와 밝은 글자 `#F1F1E8`을 사용합니다. 세이지 업무색과 살구색 휴식 바, 둥근 숫자, 직접 그린 재생·일시정지 기호를 적용했습니다. 두 플랫폼은 `desktop/themes.json`의 같은 팔레트를 읽습니다. 한글은 나눔스퀘어라운드, 숫자와 워드마크는 굵은 Nunito를 OFL 라이선스와 함께 배포합니다. OS에 설치하지 않고 앱 안에서 불러옵니다.

모서리 반경 30, 테두리 1, 그림자 반경 4와 깊이 3, 투명 여백 포함 약 270×86의 크기는 유지합니다. 위젯 전체 불투명도는 평소 45%, 마우스를 올렸을 때 95%입니다. Windows에서는 위쪽 호버 영역에 숨기기·메뉴 버튼이 나타납니다. macOS는 우클릭 또는 메뉴 막대에서 설정합니다.

그날 아직 업무 기록이 없고 진행 중인 근무도 없으면 위젯 전체가 **안녕하세요! 오늘도 시작해 볼까요? / 업무 시작** 버튼이 됩니다. 비로그인 상태에서도 인사를 표시합니다. 클릭하면 로그인 여부를 확인하고, 필요하면 설정창의 로그인 탭을 먼저 엽니다. 이 경로에서 로그인에 성공하면 업무를 한 번 시작하고 시간·타임라인으로 전환합니다. 다른 기기에서 이미 진행 중인 업무가 있으면 이어받습니다. 설정 메뉴로 로그인할 때는 자동으로 업무를 시작하지 않습니다. 같은 날의 퇴근 후 재시작이나 앱 재실행에는 인사가 다시 나오지 않습니다. 삭제한 업무 기록이 있는 날도 첫 시작으로 되돌리지 않습니다. Windows에서는 인사 타일을 끌어서 이동할 수 있습니다.

기본 표시 내용은 **업무 중에는 오늘 누적 업무시간, 휴식 중에는 오늘 업무 / 이번 휴식시간과 시작·일시정지 토글 하나**입니다. 휴식 중에는 시간이 늘지 않으며 재개 시 이전 업무 합계에 이어집니다. 퇴근 후 재생 버튼은 같은 날 업무를 다시 시작합니다. 퇴근·대시보드·로그아웃은 메뉴에 있습니다. 잔업 구분은 제거했고 과거 잔업 기록도 업무 합계에 포함합니다. 설정창은 Day 1과 같은 사이드바와 둥근 카드로 구성하며 로그인·디자인·만든놈 탭을 제공합니다. 디자인과 만든놈은 로그인 없이 열 수 있습니다. 디자인 탭에는 시작 전·업무 중·휴식 중 미리보기가 있고 설정창도 크림·다크에 맞춰 바뀝니다.

디자인 설정의 **테마**에서 크림·차콜·사용자 지정을 선택합니다. 배경이나 글자색을 바꾸면 사용자 지정으로 저장합니다. 기본 디자인 복원은 크림으로 돌아갑니다. 이전의 기본 어두운 색은 크림으로 이전하고 직접 설정한 색, 위치와 투명도는 보존합니다. 두 불투명도(평소 / 마우스를 올렸을 때)의 범위는 각각 10–100%이며 낮을수록 더 투명합니다. 배경뿐 아니라 글자·버튼·바를 포함한 위젯 전체에 적용합니다. 이전 버전의 단일 불투명도는 마우스를 올렸을 때의 값으로 가져옵니다. 현재 상태·누적 휴식시간·현재 구간명은 각각 켤 수 있고 기본값은 모두 꺼짐입니다. 위치·항상 위·디자인은 기기에 저장됩니다. 자정을 넘긴 진행 중 근무는 출근일에 귀속하므로 다음 날 위젯의 ‘오늘 업무’ 합계에는 들어가지 않습니다. 토글과 메뉴는 해당 진행 중 근무를 계속 제어합니다.

업무·휴식 구간은 아래쪽 바에 시간 순서대로 배치합니다. 목표가 없으면 공백을 빼고 기록된 시간의 비율로 항상 100%를 채웁니다. 출근 직후에는 업무가 100%이며 휴식이 쌓이면 오른쪽 휴식 비율이 커집니다. 목표를 정하면 업무시간/목표시간만큼 채우고 그 안을 업무·휴식 비율로 나눕니다. 목표 8시간, 업무 4시간, 휴식 1시간이면 업무 40% + 휴식 10% + 남은 목표 50%입니다. 목표를 넘으면 바는 100%로 유지합니다. 삭제한 구간은 제외합니다.

목표는 웹의 설정 또는 데스크톱 설정창에서 시간 단위로 입력하며 빈 값은 목표 없음입니다. 계정에 저장해 기기 간 동기화합니다. 기본 목표는 없습니다. 목표 변경으로 진행 중 타이머를 종료하지 않습니다. 배경·글자색·불투명도 같은 외형 설정은 기기에 저장합니다.

## 데스크톱에서 웹 로그인 연결

로그인한 앱의 **대시보드 열기**는 같은 계정의 웹 로그인으로 이어집니다. 처음 연결하거나 다른 웹 계정이 열려 있으면 계정을 확인하는 버튼을 한 번 누릅니다. 이미 같은 계정이면 자동으로 연결됩니다. 비밀번호를 다시 입력하지 않습니다. 비로그인 앱에서는 일반 로그인 화면을 엽니다. 로그아웃은 앱과 웹에서 각각 수행합니다.

앱은 인증된 요청으로 60초 유효한 일회용 연결 코드를 발급합니다. URL fragment에는 이 코드만 넣고, 웹은 읽는 즉시 주소에서 제거합니다. 비밀번호·Firebase ID/refresh token·custom token은 URL에 넣지 않습니다. 서버에는 코드의 SHA-256 해시만 보관하고 사용자당 미사용 링크는 하나로 제한합니다. 같은 링크는 한 번만 소비할 수 있으며 만료·비활성 계정·서버에서의 토큰 취소를 확인합니다. 웹은 서버에서 받은 custom token으로 Firebase에 로그인하고 기존 사용자 UID를 유지합니다.

`Verify-Dashboard.ps1`은 새 전용 QA 계정으로 실제 Windows 클라이언트의 URL 생성과 비로그인 기본 주소를 검사합니다. 브라우저 검증용 capability 파일은 비공개 임시 출력 폴더에만 기록하고 콘솔에 출력하지 않습니다. `tools/desktop-login-test.cjs --emulator`는 인증·origin·동시 소비·재사용·만료·계정 정지/세션 취소·Rules를 검사합니다. `--live`로 실행하면 같은 검사를 실제 Firebase의 임시 계정으로 수행하고 정리합니다.

## GitHub 업데이트

공개 배포: https://bbi.hssum.kr/download / [Day 005 릴리스](https://github.com/hssum9409/daily_odd_builds-public/releases/tag/day005-v0.6.0).

Day 1의 GitHub 공개 릴리스 업데이트를 참고했습니다. 성실삐의 `day005-v` 태그와 OS별 업데이트 ZIP만 선택합니다. **자동 설치는 기본 꺼짐**이며 새 버전이 있으면 설치 여부를 확인합니다. 만든놈 탭에서 자동 설치를 켜거나 **지금 업데이트 확인**을 누릅니다. 기본 확인 주기는 6시간이며 GitHub 요청 한도에 걸리면 유예합니다. 업데이트 도우미는 업무 기록이나 Firebase 로그인 정보를 GitHub로 보내지 않습니다.

다운로드 URL·버전·크기와 ZIP SHA-256을 검증하고 압축 경로·중복·심볼릭 링크를 거부합니다. 자기 위젯만 종료한 뒤 기존 설치기를 사용해 교체하고 새 프로세스 준비 상태를 확인합니다. 실패하면 이전 버전 복구를 시도하며 진단 결과는 프로필의 `updates/`에 남깁니다. 수동 패키지 교체도 기존 `Install.cmd` / `Install.command`로 가능합니다. 업데이트 전용 ZIP은 직접 실행용이 아닙니다.

설치형 앱은 원래 받은 압축 해제 폴더를 지워도 됩니다. 설치 폴더 내부의 `Update.cmd` / `Update.command` 또는 설정창에서 업데이트합니다. Mac은 프리뷰이며 실제 설치·Keychain·업데이트·Gatekeeper·Spaces 검증 전입니다.

## 설치 및 업데이트

개발자 패키징: 저장소의 `apps/worklog`에서 `python tools/package-desktop.py`를 실행합니다. 결과는 `dist-scripts/`의 플랫폼별 ZIP입니다. ZIP을 완전히 압축 해제한 후 실행합니다. `payload.sha256`은 패키지 손상 검사이며 게시자 서명을 대신하지 않습니다.

Windows PowerShell:

```powershell
# 압축 해제한 Windows 패키지 폴더에서
.\Install.cmd
.\Status.cmd
.\Stop.cmd
.\Start.cmd
.\Update.cmd
.\Uninstall.cmd
# 설정창 및 테마를 명령줄에서 조작할 때
powershell -NoProfile -ExecutionPolicy Bypass -File .\desktop\windows\Control.ps1 -Action settings
powershell -NoProfile -ExecutionPolicy Bypass -File .\desktop\windows\Control.ps1 -Action theme -Theme dark
# 로그인 시 자동 실행을 함께 등록할 때
.\Install.cmd -Startup
```

기본 설치 경로는 `%LOCALAPPDATA%\Programs\WorklogScripts`입니다. 로그인 세션·저장 대기 요청·설정은 `%LOCALAPPDATA%\DailyOddBuilds\Worklog\production`에 DPAPI로 보관합니다. 제거 시 프로필은 유지합니다.

macOS 터미널:

```sh
# 압축 해제한 macOS 패키지 폴더에서
sh Install.command
sh Status.command
sh Stop.command
sh Start.command
sh Update.command
sh Uninstall.command
# 선택 사항: 사용자 LaunchAgent 등록
sh Install.command --startup
```

Mac 설치 및 프로필 기본 경로는 `~/Library/Application Support/DailyOddBuilds/WorklogScripts`이며 앱 파일은 그 아래 `app/`에 있습니다. 토큰과 저장 대기 요청은 Keychain에 저장합니다. 일반 디자인은 `widget.json`, 시작 오류는 비공개 프로필의 `startup.log`에 남깁니다. 자격 증명을 curl 인자로 넣지 않습니다. 터미널을 종료해도 실행되도록 표준 입출력을 분리합니다.

설치 도구는 패키지 해시·경로·소유권을 확인하고, 실행 중이면 프로세스 종료를 기다린 뒤 폴더를 교체합니다. 새 버전의 준비 신호를 확인하지 못하면 이전 폴더를 복구합니다.

## 검증기

Windows 패키지의 `Diagnose.cmd`, Mac 패키지의 `sh Diagnose.command`는 **별도 임시 설치와 프로필**에서 설치·실행·업데이트·종료·제거를 검사합니다. 기본 검사는 Firebase 데이터를 만들지 않습니다. 결과 JSON과 로그 경로를 출력합니다. Mac에서는 실제 AppKit 이벤트 루프와 Keychain 왕복도 실행합니다. Windows에서 Mac 검증을 시도하면 성공으로 처리하지 않습니다.

0.3.0부터 Windows 진단에는 `Verify-Theme.ps1`이 포함됩니다. 실제 WPF 창과 설정 컨트롤을 만들어 크림·차콜·사용자 지정, 저장 후 복원, 이전 설정 이전, 글꼴 로드, 휴식 시간 배치와 불투명도를 검사하며 로컬 합성 기록으로 PNG를 출력합니다. 서버 또는 OS 포인터 자동화 검사는 아닙니다. Mac 진단에는 AppKit 테마 선택·저장·복원과 번들 글꼴·휴식 시간 배치 검사를 추가했습니다.

0.4.0의 `Verify-Login.ps1`은 실제 WPF 인사 버튼 → 로그인 폼 → 로그인 버튼 → 업무 시작 흐름과 실패·재로그인·설정 메뉴 로그인 차이를 검사합니다. 새 전용 QA 계정 환경 변수를 넣고 OS PowerShell 5.1에서 `-STA -File desktop/windows/Verify-Login.ps1`로 실행합니다. 개인정보를 포함하지 않은 임시 프로필을 사용합니다.

실제 Firebase 전환까지 검사하려면 별도로 만든 새 테스트 계정의 `WORKLOG_QA_EMAIL`, `WORKLOG_QA_PASSWORD`를 환경 변수로 설정한 후 Windows는 `Diagnose.cmd -Live`, Mac은 `sh Diagnose.command --live`를 실행합니다. `qa-UUID@worklog.test` 형식의 전용 계정만 허용합니다. Mac live 검사는 새 계정을 요구하며 네이티브 인사·로그인 버튼을 통해 업무를 시작한 뒤 여덟 전환을 확인합니다. 관리자용 `tools/qa-fixture.cjs create <저장소 밖 비공개 파일>` 및 `cleanup <같은 파일>`은 이미 인증된 Firebase CLI로 해당 테스트 계정만 만들고 정리합니다. 개인 계정으로 자동 테스트하지 않습니다.

iOS는 `ios/verify.command`와 실제 XCTest UI 타깃 `WorklogUITests`, 공유 스킴 `WorklogVerification`을 추가했습니다. Mac에서 `npm ci`, `npm run build`, `npx cap sync ios` 후:

```sh
sh ios/verify.command build                         # 빌드만 검사
sh ios/verify.command simulator <부팅된-시뮬레이터-UDID>
sh ios/verify.command device <테스트-기기-UDID>      # WORKLOG_DEVELOPMENT_TEAM 필요
```

UI 검증에는 새 전용 QA 계정 환경 변수가 필요합니다. 로그인한 개인 계정이 있으면 중단합니다. 출근·휴식·재개·퇴근·업무 재시작, 이름 수정, 월간 통계, 재실행 로그인 유지, 로그아웃을 검사하고 `.xcresult`를 남깁니다. 자격 증명을 넣은 임시 `.xctestrun`은 종료 시 지웁니다. 빌드 성공은 UI 검증 성공과 별도로 기록합니다.

## 검증 범위 (2026-10-17)

- 0.5.3: 대시보드 기본 주소를 `bbi.hssum.kr`로 변경했습니다. 새 HTTPS 주소 연결과 API의 데스크톱 로그인 origin 허용을 확인했습니다. Windows 설치를 0.5.3으로 업데이트해 ready/visible, 크림 테마 및 270×86 크기 유지를 확인했습니다. 이 변경에서 실제 Windows 로그인 연결은 다시 수행하지 않았습니다. Mac은 preview 패키지만 생성했습니다. 위젯 인사 12와 제목 18은 유지합니다.

- 0.4.0: 승인 A/B와 시작 전·업무·휴식의 네이티브 렌더를 비교하고, 첫 비교에서 드러난 휴식 숫자 간격·입력칸 높이·테마 선택 표시를 보완했습니다. Windows WPF 검사 23개와 실제 Firebase 전용 계정의 로그인/시작/재로그인/휴식/재개/설정 메뉴 로그인 검사 12개를 통과했습니다. 테스트 계정은 정리했습니다. 세부 화면 평가는 개발 문서에 기록했습니다.

- Windows: OS PowerShell 5.1에서 컴파일·실제 WPF 실행, 설치/업데이트/손상 거부/제거, 실행 중 3회 연속 교체 확인. 실제 Firebase 로그인 및 토큰 갱신, 총 8개 상태 전환, 웹↔위젯 양방향 반영, 일시정지 중 누적 시간 고정, 디자인 적용 후 재실행 유지 확인.
- 0.3.0 추가 검사: 실제 WPF 창·설정 컨트롤에서 테마 관련 17개 검사 통과. 기본 크림, 차콜 선택 후 새 창에서 복원, 사용자 지정 보존, 이전 ARGB 설정 이전, 실제 번들 글꼴 로드, 시간·버튼 배치와 전체 위젯 불투명도를 확인했습니다. 합성 로컬 기록을 사용한 UI 검사이며 이번 테마 변경에서 실제 Firebase 전환은 다시 실행하지 않았습니다. 데스크톱 계산·설정 테스트 13개 통과.
- 0.2.1 추가 검사: 실제 Firebase 전용 QA 계정에서 인사 타일의 Click → 업무 시작 → 퇴근 → 재실행을 확인했습니다. 두 슬라이더 적용·재실행 유지, MouseEnter/Leave 처리의 전체 위젯 불투명도를 검사했습니다. PNG 최대 알파값은 기본 상태 115/255, 마우스 올림 상태 242/255입니다. 실제 OS 포인터 이동 자동화는 수행하지 않았습니다.
- Windows UI 조작 증거: 테스트 계정으로 실행한 실제 WPF 컨트롤에 앱 내부 QA 도구가 Click 이벤트를 전달했습니다. 시각 자료는 WPF RenderTargetBitmap 내보내기입니다. 사람의 마우스 조작, 실제 Alt+Tab 목록, 멀티모니터, 로그인 자동 시작, SmartScreen 정책은 검증하지 않았습니다. QA 제어는 명시적 환경 변수와 전용 QA 계정이 함께 있어야 활성화됩니다.
- 웹: 실제 배포 주소에서 전환과 동기화, 이름 수정 및 통계 확인. React 제품 UI의 재디자인은 하지 않았습니다.
- macOS/iOS: 소스 및 현지 실행 검증기 구현. 이 Windows 호스트에서는 AppKit/Keychain, Xcode 빌드, 설치·기기·시뮬레이터 동작을 실행하지 못했습니다. Mac ZIP은 preview로 표기합니다. JavaScript/셸 문법과 순수 계산 테스트는 Mac 실행 증거가 아닙니다.
- Android: 최신 업무·휴식 UI로 디버그 APK를 다시 빌드했습니다. USB 디버깅 검증은 사용자 일정에 따라 추후 진행합니다.
